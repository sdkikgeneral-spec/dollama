  [G3] の poison 方式 (9d test_g8k_arena_bitexact と同型):
    run0 = 汚染なし (既存 o_xy) / run1 = poison 0xFF (FP16 NaN) / run2 = poison 0x00。
    各 run の前に poison_arena(poison_bytes, pattern) で alloc→memset→rewind し、出力バッファも 0xCD で汚す。
    poison_bytes = min(N*K*Hout*Wout*2B, 256MiB) [col 上限] + N*Cout*Hout*Wout*2B [帯 上限] + 1MiB [整列余裕]
      = 形状から先験的に決める (実測から決めない)。実走の arena peak_request (各 run 前に reset) が
      poison_bytes 以下であることも hard (覆っていなければ空撃ちなので FAILED)。
    形状別 (既定プロセス・poison / peak_request): rep_320_128 201/180MiB, rep_640_64 101/90MiB,
      rep_1280_32 51/45MiB, G4_band_640to320_128 277/270MiB, G4_band_960to320_128 277/262MiB
      (T4 の t4_default_run2_final.log:177 の 270/262MiB を覆う)。=0 プロセスは per-n なので peak は半分程度
      (G4_band_960to320_128 のみ 264MiB = N=1 の帯分割 2 帯 (rows_cap=121) で col ≈255MiB + 帯 ≈9MiB)。1x1 形状は alloc 0 (素通り)。
