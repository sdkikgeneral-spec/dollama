  NC1 (#3): src/kernels/conv2d.cu launch_conv2d_im2col_gemm_batched の in item stride を
            Cin*H*W から Cin*H*W - W (1 行ぶんずらす) に改変。
            結果: [G2a] (X,X) と [G2b] (X,Y)/(Y,X) が im2col 経路の全 6 形状で MISMATCH FAILED。
                  1x1 経路の 2 形状 (改変の射程外) は PASSED のまま = 検査が射程どおり。
                  [G3] は全形状 BIT-EXACT PASSED のまま = 決定的なバグは [G3] 単独では捕まらない (設計どおり)。
                  [G2] floor も 3x3 形状で mismatch (compare の tol 超過)。exit=1。
  NC2 (#4): src/kernels/conv2d.cu の `if (conv_batch_enabled())` を `if (conv_batch_enabled() || true)` に
            改変 = DOLLAMA_CONV_BATCH=0 でもキルスイッチ経路 (旧 per-n ループ) へ分岐せず新経路へ迂回。
            DOLLAMA_CONV_BATCH=0 で実行。
            結果: [G1] 5/5 FAILED。内訳 = 計器側 (batched wrapper +0 期待に対し非 0) は 5/5 で red、
                  memcmp 側は batch2_1x1_bias / batch2_3x3_s2 の 2/5 のみ MISMATCH で、
                  batch2_1x1 / batch2_3x3_same / batch2_unet_c320_64 の 3/5 は新経路でも BIT-EXACT だった。
                  ★つまり memcmp 単独の [G1] ではこの迂回を 3/5 で素通ししていた。計器差分を [G1] に
                    併せたことで 5/5 で red になる。
                  加えて [G2a]/[G2b] の path check (=0 では wrapper +0 期待) が全形状 FAILED。exit=1。
