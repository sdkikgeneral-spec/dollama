### F2: 既存 9b はハード BIT-EXACT ゲートではない → **tol の議論を廃止し memcmp 不変量を hard 化 (決裁済み)**

一次証拠 (`src/tests/test_conv2d.cu`):

- `:513` `const bool bit_exact = (max_abs == 0.0f);` — この値は `:514-517` で**表示だけ**される。
- `:521` `return compare(got, ref, K, name);` = **合否は `compare()` の tol 判定** (`:87-123`)。
- `:448-449` のコメント自身が「ビット一致 (MAE=0) を**第一目標に、届かねば tol 内 (compare) を許容する**」
  と書いている。
- → 現状の 9b は、per-n 直列経路の bit 一致が壊れても **tol 内なら緑のまま通る**。

**PL の裏取りで判明した tol の実効幅** (`test_conv2d.cu:76-84`):
`rtol_for(K) = 5e-3 + 1e-5*K` / `atol_for(K) = 3e-3 + 2e-5*K`。UNet の 3x3 conv は
K = Cin·3·3 で、Cin=320 なら **K=2880 → rtol ≈ 3.4% 相対 / atol ≈ 0.061 絶対**。
**この幅を「ゲート」と呼べない。**

**決裁**: 起草時に PL 自身が出した「既存 `compare` をそのまま使え」を**撤回**。
tol の数字を議論するのをやめ、**tol に依存しない構造不変量を hard ゲートにする** (§7 の
[G1] / [G2a] / [G2b])。既存 `compare` は **floor (超えたら緩めず BLOCK)** として残す。
これで「緩和ではなく分岐」が実際に担保され、**tol を実測後に決める必要が消える**
(ゲートの自己成就の回避も同時に達成)。

## 5. 数値方針

- strided batched はタイル選択が変わるため **bit 一致は狙わない** (G-2k S2 と同種の ~1 ULP)。
  **ただし「タイル選択差が入らないはずの場所」では bit 一致を要求する** — それが決裁 2 の
  [G2a] / [G2b] (§7)。
- **tol を主ゲートにしない (決裁 2)。** `test_conv2d.cu:76-84` の
  `rtol_for(K) = 5e-3 + 1e-5*K` / `atol_for(K) = 3e-3 + 2e-5*K` は UNet の K=2880 で
  **rtol ≈ 3.4% / atol ≈ 0.061** という幅になり、これを合否の主軸にはできない。
  → **tol に依存しない memcmp 構造不変量を hard ゲートに置く** ([G1] / [G2a] / [G2b])。
  既存 `compare(..., K, ...)` は **floor** として残す ([G2])。
- **[G2] の tol は新設しない・実測後に決めない。** 既存 `compare` をそのまま floor に使う。
  「初回実測を見て tol を決める」は**ゲートの自己成就なので禁止**。
  **既存 tol (floor) を超えたら緩めずに BLOCK して PL へ上げる** — タイル選択差では説明できない量であり、
  写像バグ・帯分割バグ・bias index バグのいずれかの証拠である。
- 実測は **MAE / max_abs / max_rel / exact 率**を必ず print する
  (9b が既に `:514-517` で MAE/max_abs/exact を、`compare` が `:120-121` で max_rel を出している形式を踏襲)。
  characterization として「G-2k S2 の per-sample MAE **6.4e-05** と同オーダーか」を併記する
  (**合否には使わない**。6.4e-05 は CLAUDE.md 計測表「UNet バッチ (G-2k S2)」行の既存記録の引用)。
- e2e の合否は既存 `test_diffusion_batch2` の **GATE2 = batch2 vs off @g=1.0 SSIM ≥ 0.999**
  (`src/tests/test_diffusion_batch2.cu:360-372`) を流用する。
- **g>1 で FP16 微差をゲートしない。** 出典は `docs/fast-mode-plan.md:274` (旧 `:244`)
  (「**教訓 (非交渉)**: CFG 増幅下 (g>1) で FP16 の微差をゲートしてはいけない。被験変数は g=1.0 で分離する。」)
  と**同 doc「検証・ゲート」節の引用ブロック** (grep: `guidance 倍に増幅`。増幅の機序と G-4k S3 初版の実害
  0.996533 < 0.999)。★**行番号の是正 (2026-09-20)**: 旧記述 `:345-347` の現物は `:390-391`
  (`:344-347` は別物の prof_unet_fast_warm resnet バケット表で、**飛び先が実在するもっともらしい表なので
  着地ミスに気づけない**型の誤り = 2026-09-05 の監査 BLOCK B-1)。

### アンカー 3 本と、アンカー 3 の位置づけ (2026-08-24 再決裁)

- アンカー 1 = **プロセス 1 と 3 の同一構成再測** (ドリフト幅)

- アンカー 3 = **T2c (`conv2d` 変更前) vs T7 の `CONV_BATCH=0` (変更後)** = **キルスイッチ復元性の
  「秒レベルの参考対照」** (★**hard 検査ではない**。下記)

**T2c を T4 に混ぜない理由**: `conv2d` 変更後のツリーでは「変更前の `=0`」を作れないので、
**混ぜると取れない**。だから T2b → T2c → T3 → T4 の順序は強制する。

#### ★アンカー 3 は「復元性の hard 検査」ではない (初版の設計誤りを是正)

**初版はアンカー 3 を「キルスイッチが旧経路を本当に復元しているかを数値で押さえる」検査として書いた。
これは本書自身の 2 つの原則に違反していた**:
① §3「★分母の決裁」= **絶対秒の据え置きはドリフトに耐えない**
② §8 ケース B「マージンを対照の代替にしない」= **別セッション跨ぎの差を対照なしで読めない**
T2c と T7 は**別セッション**なので、アンカー 1 (同一セッション内の幅) をそのまま当てられない。
★**PL の弁**: 「アンカー 3 を良い設計と評価したのは私の誤り。文書自身の原則を、自分で作ったアンカーで破っていた」。

**再定義 (3 点)**:
1. **「一致」は帯で定義する** — **帯 = ±max(アンカー 1 で実測したドリフト幅, 10%)**。
   ★**幅の正規化 = |P1 − P3| / P1 (先行プロセス P1 比)**。理由: 床の根拠である下記 **+9.9%**
   自体が前値比 ((1.41299 − 1.28564) / 1.28564 = 0.099) で算出されており、`max(実測幅, 10%)`
   の両辺を同一の正規化で比較するため (平均比だと同じ実測が 9.4% になり床との対応がずれる)。
   下限 10% の根拠は G-4k S3 の実測ドリフト **+9.9%** (`docs/fast-mode-plan.md:344-347` の
   同一走行内 default 再測 **1.28564s → 1.41299s**)。
   ★**`max()` を採る理由**: アンカー 1 は**同一セッション内**の幅なので、**別セッション跨ぎの
   アンカー 3 に対しては下限としてしか使えない**。跨ぎの方が狭いという主張には根拠がないため、
   **実測幅が 10% を下回っても帯は 10% で床を張る**。
   比較する量は「**同一構成 (`fast+epilogue`) の resnet バケット絶対秒**」に限る。
2. **帯超過時は断定しない**。手順は下記「帯を外れたときの 3 段」。
3. ★**数値的な復元性の hard 検査は [G1] の memcmp が担う** (§7)。
   **秒側の hard 担保は T4 の「構造保存の要件」**(キルスイッチ経路が旧コードへ分岐していることを
   差分レビューで確認する) が担う。**アンカー 3 はその 2 枚の上に載る「確認の窓」に降格する。**

#### なぜ降格してよいのか (この論理が成立して初めて降格できる)

アンカー 3 が本当に捕まえたい失敗形は、**承認済み設計から自然に生えるもの** — すなわち
**不変条件 3 の「`rows_cap` を N で割る」がキルスイッチ経路にも漏れる**ケースである。
そのとき `CONV_BATCH=0` は **bit 一致 ([G1] 緑) のまま帯分割回数だけ増えて秒が悪化する**。
**この失敗形を秒で検出しようとしたのが誤りで、構造で封じるのが正しい** (T4 の DoD に追加済)。
→ 復元性は **[G1] (bit) + 構造保存 (秒の原因側)** の 2 枚で担保される。
**2 枚が揃った時点で、アンカー 3 は「万一を見る窓」に落として差し支えない。**
逆に言えば、**T4 の構造保存要件を満たさないままアンカー 3 を窓に降格させてはいけない。**

#### 帯を外れたときの 3 段 (事前に固定・実走後に決めない)

1. ★**結論を書かない。「非復元の証拠」という語を使わない。**
2. **T2c 時に保存した exe を、T7 のセッション内で隣接再走**して**同一セッション比較に変換**する。
   これで初めてアンカー 1 の幅を正当に適用できる。
   - **T2c の DoD に「exe / build 成果物を保存する」が入っているのはこのため。**
     保存していないとこの手順が実行不能で、**帯超過が永久に未解決のまま記録に残る。**
   - 再走は **SAC 状態を変えないまま同一セッション内で行う**。
     ★**「既走の exe は allow-list 済みだから大丈夫」とは書かないこと** (裏取りしていない主張)。

### θ の導出 (実測前に固定・実測後に動かさない)

**正規化は全体最大ノルム**:

> **E = max_i |got_i − seq_i| / max_j |seq_j|**

- ★**E のスコープ = batch 全 item**: 添字 `i` / `j` は **batch 全 item (n = 0 .. batch-1) の全出力要素
  (合計 `M・N・batch` 個)** を走る平坦な要素添字であり、**特定の n に閉じた max ではない**
  (floor 側の「n=0 / n=1 の両 item に適用」と対称)。分母 `max_j |seq_j|` も同じ全 item 集合上の最大。
  **後述 θ 節の `max_i Σ_k |A_ik|` の `i` は A の行インデックスで、ここの `i` とは別物**。
- **ゼロ近傍で自爆しないのはこの正規化のため** (per-element 相対では小さい要素で発散する)。
- `max_j |seq_j| == 0` のケースは**不可** — **データ生成側で非ゼロを保証する**。

★**compute type の前提 (θ の導出はこれに依存する)**: **batched も既存 `gemm_cublas` と同じ
`CUBLAS_COMPUTE_32F` を使うこと** (現物 = `src/kernels/gemm.cu:431`)。
同ファイルには **FP32 経路が既定で `CUBLAS_COMPUTE_32F_FAST_TF32` を使う前例**がある
(同 `:440` のコメント / `:477` の三項演算子) ため、**batched ラッパでうっかり TF32 や
`CUBLAS_COMPUTE_16F` を選ぶと `u32 = 2^-24` の前提が崩れ、下記の θ は理論上限でなくなる**
(TF32 は仮数 10bit・16F 蓄積はさらに粗い)。**compute type を変えたいなら θ を先に導出し直して PL へ。**

**θ は 2 項の和**。batched 側と直列側は「FP16 入力 / FP32 蓄積 / FP16 出力」で**違うのは蓄積順だけ**なので:

1. **FP32 蓄積順の差**: 内積の丸め誤差の古典上限 `|err| ≤ γ_K・Σ_k |a_k b_k|`、`γ_K ≈ K・u32`、`u32 = 2^-24`。
   両側の差はその 2 倍 → **2・K・2^-24・Σ_k |a_k b_k|**。
2. **FP16 出力丸めの差**: 正規化数の相対 ulp 上限 **2^-10**。

> **θ = 2^-10 + (2・K・2^-24・S) / max_j |seq_j|**
>
> ここで **S = max_(i,j) Σ_k |A_ik・B_kj|** の**分離上界**
> **S ≤ (max_i Σ_k |A_ik|)・(max_(k,j) |B_kj|)** を採り、**右辺を S として実行時に算出する**
> (2026-09-10 決裁 5・D5-2)。

- **式変形 (各 `|B_kj|` をその最大値で置換する粗い上界 = Hölder (1, ∞) 型。三角不等式でも
  Cauchy-Schwarz でもない。三角不等式が効くのは 1 つ上の `|err| ≤ γ_K・Σ_k |a_k b_k|` 側)**:
  `Σ_k |A_ik・B_kj| = Σ_k |A_ik|・|B_kj| ≤ (Σ_k |A_ik|)・(max_k |B_kj|)`。
  さらに (i,j) について最大を取る操作を**外側へ緩めて** `max_i (Σ_k |A_ik|)・max_(k,j) |B_kj|` とする。
  ★**これは厳密な上界なので θ は理論上限のままであり、緩む方向にしか動かない = false FAIL を作らない。**
  **実測由来の定数はゼロ**なので、§5 の「ゲートの自己成就」にも当たらない。
- **コストは O(MK + KN) = 一巡** (A の行ごとの絶対値和と B 全体の絶対値最大を取るだけ)。
  ★**旧版にあった「floor 用 CPU 参照の同じ三重ループで同時に累算する = 追加コストなし」は本決裁で
  無効** — 分離上界は **floor とは別ループ**で計算し、かつ floor 側はケース 1 で部分行しか回さないため、
  **同時累算はもう成立しない**。
- ★**マジックナンバーは `2^-24` と `2^-10` (FP32 / FP16 の丸め単位) だけで、実測値由来の定数はゼロ。**
- ★**上界が緩むぶん (一様 `[-1,1]` で ~2 倍の見込み・未実測) についても、下記の報告義務と
  `E > θ/2` tripwire は据え置く** — 上限に張り付くこと自体が徴候である、という趣旨は変わらない。
- ★**禁止: 初回実測を見て θ を動かすこと** (ゲートの自己成就)。**θ を超えたら緩めず BLOCK して PL へ。**
- **報告義務**: **E / θ / E/θ / MAE / max_abs / exact 率**を必ず print する。
  ★**E > θ/2 なら緑でも PL へ報告する** — **保守的な上限に張り付くのは想定外**であり、写像バグの徴候である。
- **θ の前提**: 上限の導出は入力が `[-1,1]` であることに**依存しない**
  (`S` を**実データから算出**しているため。分離上界に替えても、算出元がデータであることは変わらない)。
  ただし **floor は既存 `compare` の tol 式のまま**なので、**ケースのデータ生成は既存 `make_half`
  (`src/tests/test_gemm.cu:36`) の既定レンジを使う**こと。

### ケース A': [G2a] / [G2b] が赤 → **緩めず PL へ。tol へ逃がさない。**

[G2a] / [G2b] は「タイル選択差が入らない**はず**の場所」を突く hard ゲート
(その前提自体は cuBLAS の batched call 内の item 間一様性に関する**未検証の想定**である = §5 / §7)。
したがって **~1 ULP 級の差で赤になる可能性はゼロではない**。そのとき取る道は 1 つだけ:

- **memcmp を tol に置き換えない。閾値も入れない。** まず [G3] (3 runs 自己一致) を見て
  非決定性か系統差かを分け、`DOLLAMA_GEMM=wmma` で cuBLAS を外した経路でも同じか見る
  (`gemm.cu:376-386`)。そのうえで **PL へ上げる**。
- 前提 (item 間一様) が破れていたと確認できた場合に限り、ゲートの設計自体を PL が再定義する。
  **実装者や実走担当が現場で緩めてはいけない** (ゲートの自己成就の禁止・§5)。

### ケース B: 全ゲート緑・秒が動かない → **陰性クローズを許容。**

判定は **T7b が T7 の生ログから出す削減率**。分母は同一セットの **プロセス B (`CONV_BATCH=0`) の
`fast+epilogue` 構成** (§3 の 2 層構造)。**絶対秒での判定はしない** (B=1 の 1.212s は退役済み)。

★**3 帯の削減率定義 (−22% / −15%) は維持。ただし絶対秒は T2c と T7 で初めて確定する。**
batch2 構成の resnet バケットは **G-10k で初めて測れる量**であり (§2 F3 = T2b で計装)、
**退役した B=1 の 1.212s / 1.225s とは別系列**である。
★**この 2 系列を同じ表・同じ文の中で比較しないこと** — 混ぜると**4 回目の同型事故**になる。
T8 では「**G-10k 時点で初めて測れた batch2 resnet バケットの絶対値**」として記録し、
**別系列であることを明記**する (T8 記録スコープ参照)。
なお **e2e 倍率を合否へ昇格させないこと** (下の副次条件のとおり e2e はノイズが大きい = 元々合否に使わない設計)。

★**マージンを対照の代替にしない (決裁 2026-08-24・却下理由の明文化)**: 「−15% のマージンを取れば
同一構成の再測は要らない」は**誤り**。マージンは**差の大きさしか見ない**ので、
**ドリフトが有利方向に振れた場合 (偽の合格) を検出できない**。G-4k S3 で観測されたのは +9.9% の
減速方向だったが (`docs/fast-mode-plan.md:317`)、**方向が保証されている根拠はどこにも無い**。
対照 (プロセス 1 と 3 の同一構成再測 + `default` 行の不変性) は**方向を含めて**検出する。

| ② resnet バケットの削減率 (同一時刻帯 A/B) | 判定 | 既定 |
|---|---|---|
| **−22% 以上** | 目標達成 (G-4k 継承ゲート合格) | 新経路 **既定 ON** |
| **−15% 〜 −22%** | 部分的成功 (残りは G-9k / G-12k へ持ち越し) | 新経路 **既定 ON** |
| **−15% 未満** (ドリフト床の **~1.5 倍のマージン**を抜けない) | **秒中立 → 陰性クローズ** | **`DOLLAMA_CONV_BATCH=0` を既定**にし新経路を opt-in へ |

- **副次条件 (合否なし・裏付け)**: T7 の e2e `--fast` 相対倍率が **x1.33 帯から +0.02 以上**動くこと。
  e2e はノイズが大きいので**合否は ② で取る**。x1.33 帯の出典は既存記録

  比較する構成は **fast+epilogue (= 出荷 `--fast`)** の列に固定する (T7 の 3 構成のうちどれで見るかを揺らさない)。
  ★**現況注記 (2026-09-20・2026-09-05 の監査 Y-6)**: この **x1.33439 は pre-G-8k (2026-07-28) の値**であり、
  **現行帯ではない**。post-G-8k の実測は §14 の同一走行 (計装 ON) で **x1.30399** が採れている

  この副次条件を判定してはいけない** (窓が違う)。**計装 OFF の正典倍率は T7c がスキップされたため

### ケース B' と T6r: T6 が赤のときの事前固定分岐 (2026-09-12 決裁・T6 未実走の時点で固定)

## 9. 実装者への危険箇所 (現物確認済み・答えは書かない)

1. **`conv_bias_add_rows` を「N 倍で 1 発」にする短絡は壊れる。**
   現物 `conv2d.cu:149-160` は形状引数が `int Cout, long Ncols` の 2 つだけで、
   `const int co = static_cast<int>(idx / Ncols);` = **`row = idx / Ncols` の 1 段分解**を前提にしている。
   `Ncols` に `N*HW` を渡すと bias index が全滅する ([N, Cout, HW] レイアウトでは別の分解が要る)。
   引数追加か別カーネルが必要 — **答えは実装者が導いて単体ゲートで確認する**。
   ([G2a] は同一データを 2 本入れるので bias の**サンプル間の食い違い**は捕まえるが、
   **全サンプルで一様にずれる bias バグは捕まえない**。★受け皿は **[G2] floor と e2e GATE2** で、
   **検出下限は tol 幅** (rtol≈3.4% / atol≈0.061 = §5 が「ゲートと呼べない」と認定した幅)。
   **[G1] は数えない** — [G1] は `DOLLAMA_CONV_BATCH=0` = **per-n 直列経路**の検査であり (§7)、
   参照も per-sample N=1 呼びなので、**新経路 (batched) の一様バグには何も寄与しない**。)
2. **`[ALLOC] reserve:` の行が出ただけを reserve 成功と読むのは既知の誤読。**
   `DOLLAMA_POOL=0` でも出る (出典 `docs/fast-mode-plan.md:726-737`。機序は
   `reserve_arenas()` 自身に pool 判定が無く、printf が `device_arena_reserve()` 呼出の**後**にあり、
   no-op 判定は callee 側の早期 return で行われるため)。
   **判定は終了時サマリの `cap` / `reserved` / `chunks`** (`src/infer/unet.cu:1360-1368`)。
   reserve 不足は別行 `[ALLOC] reserve shortage:` (`src/kernels/device_arena.cu:350-358`) で
   **DOLLAMA_PROFILE 非依存・stderr へ無条件 1 回**出る。
   ★**採取時は必ず `2>&1`** — `[ALLOC]` のストリームは 2 系統に割れている (`docs/testing.md:26-30`)。
3. **帯分割は 1x1 経路には存在しない。** `conv2d.cu:306-312` のコメント (とくに `:310-311`) が
   「N=HW は単一 GEMM の C にそのまま全体テンソルへ書く (ldc=N=HW=全体行 stride) ので
   **帯分割問題は起きない**」と明記している。N 対応で 1x1 と im2col を同じ形に均そうとして、
   **1x1 に不要な band 経路を持ち込まないこと。**
4. **キルスイッチの getenv はキャッシュ型で書く。** 既存の型は `cublas_disabled()`
   (`src/kernels/gemm.cu:376-386`) と `device_arena_pool_enabled()`
   (`src/kernels/device_arena.cu:210-232`)。**プロセス単位で固定される**ため、T6/T7 の A/B は
   **構成ごとに別プロセス**になる (T7 は A→B→A の 3 プロセス = §2 N3 / §6 T7)。
   **同一プロセス内で切り替えたと記録に書かない。**
5. **`.cu` の文字列リテラルは ASCII 必須** (nvcc が CP932 解釈)。**日本語コメントは可・リテラルは不可。**
6. ★**`use_cublas` 述語の鏡写しは禁止 (T3 の分岐カウンタ)。**
   カウンタの**加算位置は、実際に通った枝の本体の中**でなければならない。
   **ラッパ先頭で `use_cublas(...)` (`src/kernels/gemm.cu:392-403`) を再評価して数えるのは不可** —
   それは述語をもう一度評価しているだけで、**分岐が本当にその枝へ入ったことの証拠にならない**
   (枝の中身が入れ替わっていても同じ値が出る = [H6] が空撃ちになる)。
7. ★**`cublas_disabled()` はプロセス固定 (getenv キャッシュ型・`src/kernels/gemm.cu:376-386`)。**
   したがって**既定経路と `DOLLAMA_GEMM=wmma` 経路を同一プロセス内で両方取ることはできない**。
   **wmma 経路は別プロセスで手動実行する必要がある** (§7b の該当節・T3 DoD ③)。
   4 の pool キルスイッチと同じ型であり、**「同一プロセス内で切り替えた」と記録に書かない**のも同じ。
